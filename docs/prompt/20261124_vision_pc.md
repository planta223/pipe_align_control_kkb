# 비전 PC 진단 인수인계 — timestamp 지연과 CAD 끝단 방향

## 요청

`pipe_align_control_kkb`의 vision-align 실물 시험이 중지됐다. 아래의 제어 PC 관측을 바탕으로 **비전 PC 호스트의 시각 동기화, 카메라 timestamp 생성 경로, pose timestamp 전달, CAD 축 방향의 재등록 일관성**을 조사하라.

먼저 읽기 전용으로 실제 실행 경로와 상태를 확인하라. 로봇·손을 움직이거나 `pre_align_ready`를 다시 실행하지 않는다. 진단을 통과시키기 위해 제어 PC의 영상 나이·학습 품질 한도를 먼저 완화하지 않는다. 확인한 사실과 추정을 구분하고, 필요한 수정과 검증 방법을 보고하라.

- `docs/preliminary_work/README_vision_pc.md`
- `docs/preliminary_work/README_control_pc.md`의 vision-align 및 진단 기록 항목

경로·옵션은 실제 프로세스에서 재확인하라. 저장소의 참조 YAML이 실제 실행 설정이라고 가정하지 않는다.

## 현재 최우선 문제: 2026-11-24 시험은 회전 전에 중지됨

제어 PC의 진단 수집 도구:

```bash
cd ~/pipe_align_control_kkb
bash main/control_pc/tools/diagnose_vision_align.sh --run-align
```

카메라 영상·카메라 정보·좌우 pose 수신 확인은 통과했다. 그러나 제어기 자체의 STEP4 평균 측정에서는 영상 나이 검사로 pose가 제외돼 8초 후 다음 오류로 종료됐다.

```text
FAULT: 새 정지 영상의 좌우 쌍을 충분히 받지 못했습니다.
```

**이번 실행의 시험 회전은 0회다.** 기존 회전 반응 문제를 재현한 실행이 아니며, SDK 관절/TCP 피드백도 기록되지 않았다.

### bag에서 확인한 수신 자료

| 토픽 | 건수 | 제어 PC bag 기록 시각 − header timestamp 중앙값 |
|---|---:|---:|
| `/vision/left_pipe/pose` | 138 | 약 1.616초 |
| `/vision/right_pipe/pose` | 138 | 약 1.616초 |
| `/cam/color/compressed` | 36 | 약 1.581초 |
| `/cam/color/camera_info` | 98 | 약 1.585초 |

- 左右 pose의 동일 timestamp 교집합은 138개다. 좌우 짝짓기 실패가 주원인은 아니다.
- frame 이름은 `camera_left_optical_frame`이다.
- 제어기의 `max_pose_age_s`는 1.0초다. 수신 건수가 있어도 이 조건을 넘으면 측정에 사용하지 않는다.
- 카메라 원본과 camera_info에도 비슷한 공통 편차가 있다. pose가 원본 영상보다 추가로 약 35ms 오래된 점과 구분한다.
- 수신 시각 차이만으로 **PC 시계 오차와 실제 처리·전송 지연을 분리할 수는 없다.** 공통 시각 편차 또는 timestamp 기준 문제를 우선 점검한다.

### 제어 PC의 시각 상태

진단 후 조회 결과:

```text
Timezone=Asia/Seoul
NTP=yes
NTPSynchronized=yes
chronyc tracking: System time 약 0.000312초 fast of NTP time
Leap status: Normal
```

이 결과는 제어 PC에서 확인한 값이다. 비전 PC도 동기화됐다는 근거는 아니다.

## 비전 PC에서 먼저 실행할 명령

**Docker 내부가 아닌 비전 PC 호스트 터미널에서, 한 줄씩 각각 실행한다.** 사용자가 앞서 `too many arguments` 오류를 보고했으나 정확한 입력 명령은 아직 확인되지 않았다.

```bash
timedatectl status
```

출력이 끝나면:

```bash
chronyc tracking
```

chrony가 설치·실행되지 않았다면 현재 사용 중인 NTP 서비스를 확인한다. 결과를 보기 전에 특정 동기화 서비스나 시계 조정 명령이 적용 가능하다고 단정하지 않는다.

## timestamp 경로 조사

1. 카메라의 `header.stamp`가 시스템 ROS 시각, ZED 촬영 시각, 센서 자체 시계 중 무엇에서 만들어지는지 추적한다.
2. 원본 이미지와 camera_info가 같은 시각 기준을 쓰는지 확인한다.
3. FoundationPose pose가 원본 촬영 timestamp를 보존하는지 확인한다. 추론 완료 시각으로 바꿔 지연을 숨기지 않는다.
4. 카메라 호스트와 추적 컨테이너의 실제 실행 위치, PC 간 동기화 상태, timestamp 단위와 변환을 확인한다.
5. 동기화가 정상이라면 큐 적체·오래된 프레임 처리·센서 시각 변환의 고정 편차를 조사한다.
6. 수정 후 제어 PC에서 같은 기준으로 영상 나이를 재측정해 1초 한도 안에 들어오는지 확인한다.

## 추가 문제: CAD 축 반전으로 오른쪽 끝단 의미가 바뀜

사용자가 정렬하려는 면은 양쪽 중앙을 향하는 안쪽 플랜지다. `docs/vision_pc/20261119_170348.jpg`에서 빨간 원으로 지정했다.

- 11월 19일의 등록에서는 왼쪽 CAD 축 −X, 오른쪽 +X였고, 두 목표 면이 모두 CAD Z=0에 해당했다.
- 11월 24일 수집에서는 **양쪽 CAD 축이 모두 대략 −X**다. 오른쪽 원점이 바깥쪽 끝단에 놓였다.
- 저장한 원본 영상과 camera_info를 이용해 투영 위치를 대조했다. 이번 등록 기준 목표 면은 **왼쪽 Z=0, 오른쪽 Z=316mm**에 해당한다.

이번 bag 마지막 pose에서 계산한 카메라 좌표:

| 후보 끝단 | X / Y / Z (m) |
|---|---|
| 왼쪽 Z=0 | −0.01620 / −0.13023 / 0.35922 |
| 오른쪽 Z=0 | 0.51400 / −0.11908 / 0.34969 |
| 오른쪽 Z=316mm | 0.19830 / −0.12879 / 0.35960 |

현재 제어 설정은 아직 `left_endpoint_z_m: 0.0`, `right_endpoint_z_m: 0.0`이다. timestamp 문제 해결 후에도 이번 등록에서는 끝단 대응을 맞춰야 한다. **위 값을 모든 추적 재시작에 고정 적용할 수 있다고 가정하지 않는다.**

대칭 형상, 초기 등록, 출력 좌표 변환, `--z-axis-stabilization` 등의 실제 적용 경로를 확인해 재등록 사이 CAD 축과 끝단 의미가 어떻게 바뀌는지 보고하라. 화면 표시용 bbox 축과 원본 CAD pose 축도 구분한다.

## 이전 회전 반응 문제: timestamp 해결 후 조사할 대상

11월 19일에는 실제 회전 시험까지 진행했으나 좌측 학습 품질 검사에서 중지된 기록이 있다.

- 기본 회전 시험은 축당 2°, 필요 시 팔당 3° 추가 시험 1회다. 회전 학습 이동은 양팔 최대 8회다.
- SDK 실측은 요청한 2°·3°와 일치했고, 요청·실측 회전 벡터 차이는 최대 약 0.005° 미만이었다.
- 첫 실패 실행은 신호량 4.24로 한도 3을 넘었지만, 첫 시험의 재현 잔차 0.96°가 허용 0.83°를 넘었다.
- 두 번째 실패 실행은 신호량 2.73으로 부족했다. 3° 추가 시험의 영상 축 변화는 약 0.27°, 전후 합성 불확실성은 약 0.38°였다.
- 해당 방향이 실제 파이프 축 주위 회전에 가까웠는지, 파이프가 손을 따라 회전하지 않았는지, 영상 추적 반응이 부정확했는지는 아직 분리하지 못했다.

따라서 timestamp와 끝단 계약을 먼저 해결한 뒤, 동기화된 원본 영상·SDK 실측·추정 pose로 실제 파이프 움직임과 추정 반응을 대조해야 한다. 과거 결과만으로 grasp 미끄러짐이나 FoundationPose 오류를 확정하지 않는다.

## 보고할 결과

- 실제 NTP 상태와 공통 약 1.58초 편차의 원인. 시계 오차와 처리 지연을 구분한 근거.
- 촬영 → 이미지 발행 → 추론 → pose 발행의 timestamp 계약과 실제 코드 위치.
- 수정 사항이 있다면 적용 파일·범위, 변경 전후 영상 나이와 좌우 timestamp 일치 여부.
- 재등록 시 CAD 축 방향·목표 끝단 의미를 안정적으로 유지하거나 판별할 방법.
- 아직 검증하지 못한 사항과 다음 실물 시험 전에 필요한 조치.

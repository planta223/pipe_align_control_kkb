# 제어 PC Codex 인수인계

제어 PC의 `~/pipe_align_control_kkb`에서 아래 작업을 진행하라. 먼저 [루트 README](../../README.md), [제어 PC README](../../src/control_pc/README.md), [제어 PC 준비](../preliminary_work/README_control_pc.md), [비전 PC 준비](../preliminary_work/README_vision_pc.md), `.gitignore`를 읽어라. 본문의 코드 경로는 저장소 루트 기준이다.

## 목표와 현재 상태

- 목표는 수동 teleop으로 두 Pipe를 잡은 뒤 FoundationPose pose를 이용해 양팔 xArm을 정렬하는 것이다. AnyGrasp 자동 grasping과 Omega7 공유제어는 이번 범위에 추가하지 않는다.
- 비전 실행은 사용자 정상 확인을 받았고, 제어 PC의 실제 양쪽 pose 수신은 아직 미확인이다.
- 자체 개발 코드인 `src/control_pc/rohand_selector/`는 이동 전 코드와 설정을 유지한다. `auto_align/`, 공통 `config/`, `external_reference/`는 아직 자리만 있다.
- 비전의 path/config YAML은 참조 기록만 있고 실행에 미적용이다. 이번에는 제어 PC의 실제 환경을 확인하여 필요한 YAML 작성과 적용을 진행한다.
- `docs/prompt/vision_pc_202611031745.md`는 과거 비전 인수인계 원문이다. 현재 pose 계약은 아래와 비전 준비 문서를 따른다.

## 현재 비전 출력 계약

| 토픽 | 타입 |
|---|---|
| `/vision/left_pipe/pose` | `geometry_msgs/msg/PoseStamped` |
| `/vision/right_pipe/pose` | `geometry_msgs/msg/PoseStamped` |

- 두 출력 모두 camera optical frame 기준 최종 `C_T_P`다. 위치는 m, quaternion은 `x,y,z,w`, `frame_id`는 `camera_left_optical_frame`이다.
- QoS는 BEST_EFFORT / VOLATILE / depth 1이다. 동일 영상의 좌우 결과는 같은 stamp를 갖지만 메시지 도착 시각은 다를 수 있다.
- stamp는 입력 영상의 발행 시각을 유지하며 ZED 하드웨어 취득 시각은 아니다. PC 간 시간 동기화와 실제 지연을 확인한다.
- 카메라 입력 기본값은 15 FPS다. 제어 PC에서 실제 pose 수신 주기와 끊김을 측정해야 한다.
- `tracking_status` 토픽은 제거됐다. 실패한 쪽은 pose 발행을 중단하며 이전 pose에 새 stamp를 붙여 재발행하지 않는다. 제어기는 양쪽 pose의 timestamp와 수신 timeout을 검사해야 한다.
- `--left-pipe-object-id pipe1`이면 pipe1이 left, pipe2가 right다. 초기 mask와 실제 잡은 손의 대응을 확인한다.
- 기존 실행 예시는 Z축 안정화를 사용한다. 축 주위 회전이 제거된 출력임을 고려하여 정렬에 필요한 회전 자유도를 확인한다.

## 작업 순서

1. **제어 PC 환경을 먼저 조사한다.** 실제 teleop·Omega7·xArm SDK·RoHand 드라이버와 발판 프로그램의 위치, 환경 활성화, 실행 파일, 지원 옵션, 노드·토픽·QoS를 확인한다. 비전 PC의 경로를 그대로 대입하지 않는다. 기존 프로그램은 외부 위치에 유지한다.
2. **비전에서 제어 PC로 실제 수신을 확인한다.** 비전 카메라와 이중 tracker가 실행 중일 때 아래 명령을 사용한다. 토픽 발견뿐 아니라 양쪽 메시지가 실제 도착해야 성공이다.
3. **제어 PC의 path/config YAML을 작성하고 적용한다.** 아래 YAML 작업 범위에 따라 기존 동작을 보존하며 연결한다.
4. **이동된 selector와 EEF feedback을 확인한다.** 루트에서 `colcon build --base-paths src/control_pc/rohand_selector --symlink-install`로 빌드한다. 기존 selector 설정을 임의로 바꾸지 않는다. 로봇·손 구동 없이 가능한 확인을 먼저 수행한다.
5. **Auto Align의 구동 없는 경로부터 구현한다.** `src/control_pc/auto_align/`에서 좌우 pose와 EEF feedback 구독, 동일 stamp의 pose 짝짓기, stale·누락 검사, 좌표변환, 목표 EEF 계산을 검증한다. 실제 명령 연결 전 teleop과 자율제어의 제어권 전환 및 feedback 유지 방식을 정리한다.

제어 PC 수신 확인 명령:

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=8
export ROS_LOCALHOST_ONLY=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ros2 topic info -v /vision/left_pipe/pose
ros2 topic info -v /vision/right_pipe/pose
ros2 topic echo --once /vision/left_pipe/pose --qos-reliability best_effort
ros2 topic echo --once /vision/right_pipe/pose --qos-reliability best_effort
```

## YAML 작업

- `src/control_pc/external_reference/external_reference_path.yaml`: 조사한 teleop·Omega7·xArm·RoHand의 소스/설치 경로, 환경 setup, 실행 파일 등 위치를 기록한다.
- `src/control_pc/external_reference/external_reference_config.yaml`: 외부 실행에 필요한 환경·ROS 설정·실행 옵션을 기록한다. 위치 정보는 path YAML에 두어 중복하지 않는다.
- `src/control_pc/config/`: 자체 제어 코드에 실제 필요한 YAML을 둔다. Auto Align의 토픽, 좌표계, calibration 참조, pose timeout, 정렬 목표·허용 오차·속도 제한 등은 실측 정보와 제어 요구를 확인해 설정한다. 임의의 calibration이나 검증되지 않은 기본값을 만들지 않는다.
- 기존 `rohand_selector/config/selector.yaml`은 패키지 내부에 유지한다. 공통 YAML에 같은 설정을 중복하지 않는다.
- YAML을 실제로 읽는 최소 연결 코드를 저장소 안에 구성한다. 기존 외부 프로그램은 지원하는 CLI·ROS parameter·환경변수로 값을 전달하며 수정하지 않는다. YAML 로딩 때문에 하드웨어를 자동 시작하지 않는다.
- 명령줄에 명시한 옵션이 우선하고, 생략한 항목은 YAML, YAML에도 없으면 원래 프로그램 기본값을 사용한다. boolean의 명시적 해제도 처리한다.
- 경로 기준, 필수 항목, 타입·범위와 지원 옵션을 검증한다. 알 수 없는 설정을 조용히 무시하거나 파일에만 적어 놓고 적용됐다고 보고하지 않는다.
- 실제 실행 전 최종 경로·옵션을 확인할 수 있게 하고, 값 덮어쓰기·잘못된 설정 처리는 하드웨어 없이 검사한다. 기존 직접 실행 명령은 유지하고 YAML을 사용하는 진입점을 별도로 설명한다.

## 제어 인터페이스와 좌표계 확인

- 아래는 2026-11-03 조사 기록이므로 현재 소스와 메시지로 재확인한다.
- 양팔 EEF feedback은 `/left/robot/current/base_eef_pose`, `/right/robot/current/base_eef_pose`의 `PoseStamped`였다. 위치 m, frame은 각각 `left_robot_base_frame`, `right_robot_base_frame`, 관측 주기는 약 33.33 Hz였다.
- feedback 발행은 teleop 측 Cartesian slave가 담당했다. teleop 종료 시 feedback도 끊기는지 확인하고 제어권 전환 설계에 반영한다.
- 기존 조작 경로는 Omega → `/omega7/live/{left,right}/state`(`Joy`) → Cartesian slave → xArm SDK였다. `/leftarm/Teleop_GT_Local`, `/rightarm/Teleop_GT_Local`은 당시 구독자가 없는 호환 출력이었다.
- 기존 calibration 파일과 기준 좌표계를 확인한다. `A_T_B`는 B를 A에서 표현한 변환이다. `B_T_P = B_T_C * C_T_P`에서 calibration의 C와 vision optical frame이 일치해야 한다.
- 과거 prototype은 `camera_color_optical_frame`을 기대했다. 이름 변경만으로 같은 좌표계라고 가정하지 않는다. Pipe 목표를 EEF 목표로 바꿀 grasp/TCP 관계도 확인한다.

## 범위와 결과 기록

- 수정은 이 저장소 안으로 한정한다. 외부 원본·가상환경·Docker·시스템 설정을 변경하거나 기존 프로세스를 임의 종료하지 않는다.
- 실제 로봇·손 motion command를 임의 실행하지 않는다. 수신·설정 연결과 구동 없는 계산 검증을 먼저 완료한다.
- 손에 가려진 초기 등록·추적 성능은 별도 미확인 항목이다. 정상 실행 확인을 모든 조건의 정확도 검증으로 취급하지 않는다.
- README와 준비 문서는 실제 달라진 부분만 짧게 수정한다. YAML 적용 여부, 수신 결과·주기·지연, 남은 calibration·제어권 전환 사항을 확인 사실과 미확인으로 구분해 기록한다.
- 새 YAML 연결을 구현하면 `src/control_pc/README.md`의 기존 미구현 설명도 실제 상태에 맞춘다. 비전 YAML은 계속 미적용이며 이번 작업에서 변경하지 않는다.
- 외부 코드나 대용량 실행 환경을 저장소로 복사하지 않는다. Git 전역 설정 변경과 임의 commit/push는 하지 않는다.
